# DependencyVisualizer — вариант 18

Учебное CLI-приложение C++ для анализа графов зависимостей Rust/Cargo.
Windows, Visual Studio/MSVC, C++17. XML и HTTP: встроенный Windows MSXML 6.
JSON: nlohmann/json. Получение зависимостей выполняет наш код через HTTP API,
а не Cargo и не библиотека менеджера пакетов.

## Важно перед запуском

Этот комплект не содержит json.hpp: оставьте ранее скачанный файл
src/json.hpp. Не заменяйте его пустым файлом.
Страница зависимости: https://json.nlohmann.me/integration/index.html
Для картинки нужен установленный Graphviz: команда dot -V должна работать
в среде запуска Visual Studio. Без него DOT и остальные результаты остаются,
но картинка не создаётся. Это не считается выполненным выводом изображения.

## Установка в существующий проект

Скопировать содержимое комплекта в папку, где находится
ConsoleApplication1.vcxproj, с заменой одноимённых файлов.
Существующий src/main.cpp уже подключён к проекту, повторно добавлять его
не нужно. Старые функции main из других cpp должны быть исключены.
Свойства проекта -> Отладка -> Рабочий каталог: $(ProjectDir).
Стандарт языка: C++17. Сохранить и выполнить пересборку.

## Сборка и запуск

Из Developer Command Prompt for Visual Studio в папке проекта:

    run.bat
    run.bat --test
    run.bat config_cycle.xml
    run.bat config_filter.xml
    run.bat config_itoa.xml --direct
    run.bat config_itoa.xml
    run.bat config_ryu.xml
    run.bat config_memchr.xml

run.bat каждый раз собирает проект в build, затем запускает его.
В Visual Studio: Ctrl+Shift+B и Ctrl+F5. Аргументы команды в свойствах
отладки те же: например --test или config_itoa.xml --direct.
Для обычного тестового графа оставить аргументы пустыми.
--no-image отключает запуск Graphviz; --direct выводит только прямые
сетевые зависимости; --test выполняет 12 автономных проверок алгоритмов.
Путь к XML может быть передан отдельным аргументом; по умолчанию config.xml.
Относительные пути считаются от рабочего каталога, не от расположения XML.

## XML-настройки

package: корневой пакет; в тестовых файлах — заглавные латинские буквы.
repository: HTTPS URL API-совместимого с crates.io сервера.
test_mode: true/false, выбор локальных или сетевых данных.
test_file: путь к локальному репозиторию, используется при test_mode=true.
ascii_tree: true/false, печать дерева.
filter: подстрока, чувствительная к регистру. Пустая строка не фильтрует.
Корень сохраняется всегда; совпавшие зависимости исключаются вместе с
ветвями, недостижимыми другими путями. Спецсимволы XML экранируются.

## Формат тестового репозитория

    A: B C
    B: D
    C:
    D:

Каждая вершина должна быть объявлена отдельной строкой. Пустые строки
и комментарии с # пропускаются. Повторы определений и неверные имена
вызывают ошибку. Повторяющиеся рёбра объединяются.

## Реализованные операции и функции

trim, utf8: нормализация пробелов и преобразование UTF-16 в UTF-8.
xml_value, parse_bool, valid_package, validate_config, load_config:
чтение, проверка настроек и диагностика ошибок.
print_config: вывод всех настроек ключ-значение.
parse_graph_line, read_graph: разбор локального репозитория.
request_json: HTTP с тайм-аутами, проверкой статуса, паузой 1,1 с.
fetch_dependencies: выбор max_version crate, извлечение normal-зависимостей.
build_graph: единый BFS без рекурсии, очередь и множество найденных вершин.
build_test_graph: адаптер локального источника для того же BFS.
print_graph: списки смежности.
get_load_order: алгоритм Кана по обращённым рёбрам, зависимости раньше
потребителей; цикл делает порядок невозможным, но граф сохраняется.
dot_quote, save_dot: экранирование и запись graph.dot, включая изолированные
вершины. print_ascii_tree: нерекурсивное конечное отображение со ссылками
[already shown] на ранее раскрытые пакеты.
show_graph_image: создание graph.png через dot и открытие изображения.
display_result: общий вывод. check, run_tests: автоматические проверки.
main: выбор режима и обработка ошибок.

## Примеры и проверка

config.xml: шесть достижимых пакетов; порядок F D E B C A.
config_cycle.xml: обход заканчивается, порядок недоступен из-за цикла.
config_filter.xml: E исключён, остаётся пять пакетов.
config_itoa.xml, config_ryu.xml, config_memchr.xml: три заготовки настоящих
пакетов. Их нужно реально запустить; результаты и картинки НЕ приложены.
Каждый запуск перезаписывает graph.dot и graph.png.
Для сдачи сохраните скриншоты трёх запусков отдельно.
Тесты не проверяют весь HTTP/MSXML/Graphviz; успешный --test не заменяет
проверку сетевого режима и изображения.

## Ограничения и сравнение с Cargo

Вершина — имя пакета, не пара имя+версия. Для каждого имени независимо
выбирается max_version. Ограничения req, feature resolution, target,
yanked-версии и Cargo.lock не разрешаются как в Cargo.
Включаются ВСЕ объявленные normal-зависимости, в том числе optional,
вне зависимости от выбранных features и платформы. build/dev исключаются.
Поэтому результат — граф объявленных normal-зависимостей последних версий,
а не точный граф сборки cargo tree. Возможны лишние связи и циклы.
Порядок топологический только для этого графа, а не журнал работы Cargo.
При достижении 200 вершин выполнение прерывается с ошибкой, неполный граф
не выдаётся за полный. API-запросы требуют доступа к интернету.

Для фактического сравнения установите Rust/Cargo и в отдельном временном
проекте добавьте выбранный пакет, затем выполните cargo tree -e normal.
Сравнивайте версии, features/optional и платформы. Команду cargo используйте
только для внешней проверки, не из программы анализа.
Нельзя заранее утверждать, что результаты совпали: сравнение ещё надо
выполнить и записать реальные отличия.
